# Image and video workflows

## Images

Generate one or more images:

```sh
python3 scripts/grok.py image generate "A paper boat in a summer storm" \
  --n 4 --aspect-ratio 21:9 --resolution 2k --quality medium \
  --output boat.jpg
```

Edit one image or combine up to five source images in one edit:

```sh
python3 scripts/grok.py image edit product.png \
  "Place the product on a rainy city street" \
  --reference-image model.jpg --reference-image background.jpg \
  --aspect-ratio 16:9 --resolution 2k --quality medium \
  --output campaign.jpg
```

The default model is `grok-imagine-image-2.0`. Generation supports `--n 1..10`, aspect ratios including `auto`, `21:9`, and `5:2`, resolutions `1k|2k`, and qualities `low|medium|auto`. Editing supports one positional image plus up to four `--reference-image` inputs and accepts the same aspect-ratio, resolution, and quality controls. Inputs may be local paths, public URLs, or data URIs; the CLI does not accept xAI `file_id` values directly.

If `--quality` is omitted, xAI currently chooses `auto` (currently low for generation and medium for editing). Output price varies by quality and resolution; select an explicit tier when predictable cost matters. Image URLs returned by xAI are temporary; the CLI downloads them immediately. Image generation/editing options and defaults may change; verify current behavior against the [official generation](https://docs.x.ai/developers/model-capabilities/images/generation), [editing](https://docs.x.ai/developers/model-capabilities/images/editing), and [multi-image editing](https://docs.x.ai/developers/model-capabilities/images/multi-image-editing) docs.

The official retirement notice says `grok-imagine-image-quality` will route to Image 2.0 at `quality: low` starting **November 2, 2026**. This does not change this CLI's current `grok-imagine-image-2.0` default or justify changing its quality behavior ahead of that date. See [xAI's migration notice](https://docs.x.ai/developers/migration/imagine-image-quality-nov-2).

## Videos

Text-to-video:

```sh
python3 scripts/grok.py video generate \
  "A paper boat drifts under warm streetlights" --duration 8
```

Image-to-video:

```sh
python3 scripts/grok.py video generate \
  "The boat moves naturally with the current" \
  --image boat.jpg --duration 6 --resolution 720p --aspect-ratio 16:9
```

Reference-to-video with first/last frames and intermediate keyframes:

```sh
python3 scripts/grok.py video generate \
  "The subject walks through the scene, then turns toward camera" \
  --image first.jpg --reference-image outfit.jpg \
  --keyframe 3.0=middle.png --last-frame final.png \
  --duration 8 --resolution 720p
```

Reference voice IDs are preset xAI voices, not user-uploaded voice samples:

```sh
python3 scripts/grok.py video generate \
  "<AUDIO_0> introduces the product shown in <IMAGE_0>" \
  --reference-image product.jpg --reference-voice eve
```

| Workflow | Default model and controls | Limits |
|---|---|---|
| Text-to-video | `grok-imagine-video-1.5`; CLI defaults to 6s, 720p, 16:9 | 1–15s; 480p/720p/1080p. 1080p is documented for Video 1.5 text-to-video; the CLI rejects it for the classic slug. |
| Image-to-video | Same; pass `--image` | 1–15s. 1080p is documented for Video 1.5 image-to-video. |
| Reference-to-video | Video 1.5; repeat `--reference-image` and/or `--reference-voice` | Up to 7 images and 3 preset voice IDs; max 720p. Classic `grok-imagine-video` retains up to 3 reference images, but cannot combine them with `--image`. |
| First/last frames and keyframes | Video 1.5; use `--image`, `--last-frame`, and repeat `--keyframe TIMESTAMP=IMAGE` | Up to 4 keyframes; timestamp must be greater than 0 and less than duration. xAI snaps timestamps to a 1/3-second grid and rejects collisions. This CLI restricts reference- and frame-pinned requests to 720p because 1080p is only documented for Video 1.5 text-to-video and simple image-to-video. |
| Video edit | Defaults to `grok-imagine-video` | MP4 input with supported codec, at most 8.7s; output retains input duration/aspect ratio and is capped at 720p. |
| Video extend | Defaults to `grok-imagine-video`; CLI defaults the added duration to 4s | Input 2–15s; added segment 2–10s; output retains input aspect ratio/resolution, capped at 720p. The API default, if duration is omitted, is 6s. |

Video 1.5 also accepts up to three preset voices as `--reference-voice <voice_id>`; use `<AUDIO_0>`, `<AUDIO_1>`, and `<AUDIO_2>` in the prompt to refer to them. User-provided voice samples are only available to trusted partners. Audio is generated by default; use `--no-generate-audio` for silent output. For image-to-video, xAI defaults to the source image's ratio, but this CLI sends 16:9 unless overridden; match the source with `--aspect-ratio` to avoid stretching. See xAI's [video generation](https://docs.x.ai/developers/model-capabilities/video/generation), [image-to-video](https://docs.x.ai/developers/model-capabilities/video/image-to-video), and [reference-to-video](https://docs.x.ai/developers/model-capabilities/video/reference-to-video) docs.

Edit or extend an existing video:

```sh
python3 scripts/grok.py video edit source.mp4 "Change the scene to a rainy night"
python3 scripts/grok.py video extend source.mp4 "The subject exits frame" --duration 4
```

The edit and extend defaults use `grok-imagine-video`, matching current xAI examples. The official docs do not confirm whether `grok-imagine-video-1.5` supports either endpoint; `--model` remains available to override, but 1.5 edit/extend compatibility is unverified. The CLI does not preflight video container/codec/duration constraints, so invalid inputs can still incur a request charge. See xAI's [video editing](https://docs.x.ai/developers/model-capabilities/video/editing) and [video extension](https://docs.x.ai/developers/model-capabilities/video/extension) docs.

## Async lifecycle and resuming

Video requests submit once, return a `request_id`, then poll via GET. The CLI never automatically resubmits a timed-out request. Use the ID from the error/result to inspect or resume it:

```sh
python3 scripts/grok.py video get REQUEST_ID
python3 scripts/grok.py video resume REQUEST_ID --max-wait 600
```

`video get` performs one status GET. `video resume` performs GET polling and downloads the completed temporary URL; neither issues a generation POST. If resume times out, run it again with the same ID. A request that becomes `failed` or `expired` cannot be resumed. See the [official video REST API](https://docs.x.ai/developers/rest-api-reference/inference/videos).

## Local safety limits

Local-file data URIs are capped at 20 MiB per image and 200 MiB per video; downloaded media is capped at 200 MiB. These are CLI safeguards, not xAI service limits. Output conflicts and unusable parent directories are checked before paid submissions. `--overwrite` allows replacing files, not writing to a directory.
